# IronWeaveDrama

AI 剧集创作与制作系统。

以整部剧为项目，按季、集组织创作，角色等资源由全剧共用。支持小说片段改编、剧本编辑、人物与场景提取、共享资源档案、基础角色板和场景参考图生成、服饰／道具素材库、手动定妆，以及可编辑的分镜与时长估算。

## 运行

需要 Node.js 22.13 或更新版本。没有第三方依赖，无需 `npm install`。

```bash
npm start
```

打开 <http://127.0.0.1:3000>；远程访问使用 `http://服务器IP:3000`。按 `Ctrl+C` 停止。

端口被占用时：

```bash
PORT=3001 npm start
```

## 基本使用

1. 在“设置”中添加 API 配置，填写名称、类型、接口地址、密钥和模型。支持多条 OpenAI 兼容配置；地址需包含服务要求的版本路径，程序不会自动补 `/v1`。
2. 创建项目，选择画风和画面比例，在创作空间添加季和集。
3. 进入本集“剧本”，粘贴小说原文、选择大语言模型并生成；剧本和改编说明可以分别编辑、保存。
4. 从本集已保存剧本提取人物与场景，核对、删除错误项后确认关联或新建共享档案。重新提取会重新调用模型，不屏蔽上次删掉的项。删除提取项时，若本页还有未保存修改或模型恢复内容，会先提示；确认继续会在删除成功后刷新并放弃这些输入，取消或失败则保留。
5. 在“基础演员”资源库完善角色档案，可上传身份参考图，再选择对应 API 生成角色板。角色板模板适用于年龄明确为 18 岁及以上的角色，固定 16:9。
6. 在场景资源库完善固定环境描述，可上传环境参考图，再生成无人场景参考图，沿用项目画风与画面比例。人物和场景均无参考图时使用文生图，有参考图时使用图生图；参考图支持 PNG、JPEG、WebP，最多 5 MiB。
7. 在“服饰”“道具”资源库添加名称、说明和参考图，可替换或移除图片。素材由全剧共用，暂不提供素材图片自动生成。
8. 在“定妆”中新建条目，选择一个基础演员及可选的多件服饰／道具，自己填写提示词并先保存；核对页面显示的实际参考图顺序，再选择图生图 API 并点击生成。不会自动搭配或用 LLM 改写提示词；定妆沿用项目画风，采用与基础演员相同的横向 16:9 四视图（脸部正面特写、正面全身、左侧全身、背面全身），不覆盖演员基础图。
9. 进入本集“分镜”，选择大语言模型、设置单镜时长上限并生成文字分镜。逐镜核对构图、动作、对白、声音和预计时长；勾选出镜角色后，可手动选择该基础演员的定妆并查看照片。可增删、排序后确认保存；「删除全部镜头」经确认立即清空本集，无需再保存，不影响剧本、共享资源或其他集。全剧时长汇总只计入已确认且依据版本有效的集，并标注尚未规划的部分。镜头图与视频生成尚未接入。

保存内容、上传参考图不会调用模型。生成和“测试模型”可能计费，失败不会自动重试。已有剧本或分镜重新生成时会确认替换；需要保留旧稿时请先自行备份。

定妆生成会发送实际图片文件：先基础演员（优先有效角色板，否则上传参考图），再按编号排列的服饰、道具。已选图片缺失会在调用模型前停止；最多选择 50 件素材，参考图合计不超过 32 MiB。使用已保存的图生图配置，固定向 `/images/edits` 发送 `image[]` 多图字段；接口须支持这一协议，普通单图 API 测试通过不代表多图兼容，不会改单图或自动重试。生成图片和输入版本保留历史；演员、素材或创作依据变化后，旧定妆照标为旧依据，不会自动付费重生成。分镜定妆只保存你手动选择的演员关联与图片版本，不自动挑选、改写镜头或生成图片；缺图／旧依据会提示，可先保存文字关联。已有选择不会因生成新图而自动换图；删除定妆或清除已选图片后，需取消或重新选择。重新生成分镜会替换镜头和定妆选择。

演员、场景和定妆的“AI修图”复用同一套遮罩编辑器，支持画笔、擦除、撤销／重做、缩放／平移与遮罩下载。当前真实遮罩修图接口尚未接入，“开始修图”禁用；这些操作不会调用模型，也不会回退为无遮罩的整图重生成。

剧本生成、人物／场景提取和分镜生成不设本地主动等待时限，完整结果通过校验后才保存。等待期间请勿重复提交；服务商或网关仍可能中断连接。

## 数据与安全

- 数据保存在 `data/drama.sqlite`，刷新或重启后保留；请备份 `data/`，删除该目录会丢失项目资料。
- API 密钥以明文保存在本地数据库中，`data/` 不纳入 Git。请妥善保管数据和备份。
- 删除操作会按确认框说明级联删除相关内容，无法撤销。
- 服务默认监听 `0.0.0.0`，没有登录鉴权。能访问服务的人可以查看和修改资料、使用已保存的 API；请仅允许可信 IP 访问，不要直接向所有公网用户开放。

## IronWeave protocol 2 与文件交付

旧同步 JSON 图片/文字配置继续使用 `legacy`，不会根据响应猜协议。设置页可明确选择 `ironweave2`（模型名固定 `ironweave`，Base URL 仍需包含 `/v1`），并选择图片或视频类型。遮罩编辑、文字、FL2VA、云端视频和自动续写不属于新协议接入范围。保存配置、打开页面和保存片段都不调用模型；只有用户点击生成/测试才提交一次请求，提交未知不会自动重发。

### 隔离路径和技术验收

- `IRONWEAVE_DRAMA_DATA_DIR`：数据库目录，默认仍是仓库 `data`。
- `IRONWEAVE_DRAMA_MEDIA_DIR`：新媒体专用目录，默认 `data/generated-media`。每操作固定 UUID 的 `.part`/`.media`，不扫描或删除已有作品目录。
- `IRONWEAVE_FFPROBE` / `IRONWEAVE_FFMPEG`：完整媒体探测/解码程序的绝对路径（未配置时从 PATH 寻找）。**缺工具或解码失败不发送 ACK**。解码使用受控参数、不通过 shell、不上传媒体；先核对尺寸，再完整核对帧数/帧率/时长/音轨并解码，进程输出和耗时有界。WebM 还要求 8 KiB 内的完整 EBML 头明确声明唯一 `DocType=webm`，画面编码为 VP8/VP9/AV1、音轨为 Vorbis/Opus；普通 Matroska 不因共享魔数而被视为 WebM。
- SQLite 增量迁移至版本 18；保留旧 BLOB，不把旧作品搬迁到文件系统。首次升级业务库之前须备份数据库和新媒体目录，本轮测试仅使用内存/专用临时库。

protocol 2 使用原生 HTTP 单次请求、标准 multipart 编码和网络空闲时限，不套推理/排队总超时。接收器按长度逐 part 解析，限制头/事件/传输缓冲，校验任务、序号、版本、固定回执、期限、MIME 关闭和正常 EOF；视频不整段聚集 Buffer。GET 只整取同一文件，不使用 Range，不重新推理。本地已保存视频的播放路由另支持单段字节范围，与 Iron GET 不混用。

### 保存、恢复与人工采用

`/projects/:id/operations`（设置测试使用 `/operations`）展示操作、来源版本、本地保存状态、远端状态、交付确认和人工采用，提供恢复/同回执核对。生成页的 NDJSON 明确协商 `Accept: application/x-ndjson`，进度与最终业务结果分开；普通 CRUD 和旧 JSON 调用保留。停止/离页中止当前请求：生成阶段由 Iron 裁决取消，可交付后只停止当前传输。返回页面不会自动提交新生成。

accepted 立即持久保存任务编号及受理快照。临时文件完整校验后 fsync → 原子 rename → 目录 fsync → SQLite 保存媒体/业务/来源关联，之后才 ACK。跨文件/数据库不存在假事务：rename 后数据库失败，按原操作 ID 找回；残片不 ACK，完整残片须重新验证才可发布。数据库已保存且文件重验正确但 ACK 结果未知，直接核对同一回执，不先重复写入 saved；rename 后持久化中断则重新刷盘文件及目录后提交关联。损坏文件仅在窗口内重取同一产物，不重新生成。即使期限过去，也不在本地阻止已成功回执的幂等核对。accepted 已收到、output_begin 丢失时，可以 GET 同一任务并校验权威响应头；accepted 也丢失则不猜任务或重发 POST。

新生成媒体不会自动替换演员/场景/定妆或片段。人工采用会重新核对来源；旧依据保留为历史，不覆盖当前版本。完整本地文件即使确认未确定也可人工采用，但不会伪造 `succeeded`。采用的新图片通过 `generated_media_links` 关联文件，旧 BLOB 路由仍然可读。

不扫描或自动回收未登记的新媒体/旧作品目录。项目删除遵循明确的持久清理流程：

- 存在 `active=1`、本进程仍在接收/恢复的操作，或 `delivering` 且 ACK 未确认时返回409，先在仍可达的项目历史停止/恢复/核对。release 只解本地防重，不是确认或取消证明。
- 允许删除时，在同一 SQLite 事务将本项目操作 UUID 写入 `media_cleanup`，删除对应文件链接、操作及项目；回滚不删文件。其他项目与全局配置不受影响。
- 提交后按待办 UUID 精准 unlink `.part`/`.media`，同步目录后才移除待办。不递归删除、没有目录扫描；失败保留持久待办。HTTP 每次最多尝试25项，未清完返回并显示“项目已删除，媒体清理待重试”，不伪装已全部删除。
- `src/media-cleanup.js` 的 `cleanupPendingMedia(db, { directory, projectId, limit })` 可显式幂等重试，limit为1–100、默认50；server启动最多重试100项并报告剩余待办。批次未完成或存储故障解除后可继续调用，重复删除/ENOENT安全。函数拒绝在活动事务中执行。
- 删除资源/季/集只清理已被级联删除的悬空图片链接；项目级新生成历史及文件保留，仍能播放和核对交付。动态来源状态标记删除/过期并禁止采用，不再承诺新历史文件随资源即时删除。整项目删除才覆盖该项目全部已登记新媒体。

来源状态由只读 `sourceStatus(db,row)` 依据当前演员/场景/定妆/分镜/片段与素材快照计算，并由历史 API/页面和采用门禁共用。保存、ACK、来源有效性和人工采用分别展示；旧来源显示“已过期/来源已删除”，原 adopted 标记显示“曾采用，当前已失效”，不隐式替换或删除作品。来源失效不妨碍已保存媒体播放或恢复同任务交付。回退旧版本程序前必须处理新文件关联行，不能直接让不理解文件关联及版本 18 清理待办的旧程序把空 BLOB 占位当成图片；没有自动破坏性降级迁移。

### 镜头、片段与视频

从本集文字分镜页面进入“镜头构图 / 视频片段”（`/projects/:id/episodes/:episodeId/media`）。先核对文字分镜，再逐镜人工填写构图提示词、明确尺寸和图片配置；实际参考图按页面所示顺序上传。片段可以包含一个或多个镜头，`shots` 数组明确顺序，保存不可变来源/素材版本快照。

六段名称和顺序严格沿用 `docs/minimax-h3-ref2va.md`：`subject_definitions`、`summary`、`retention_analysis`、`detailed_description`、`overall_soundscape`、`non_diegetic_music`。人工编辑，程序不调用 LLM 扩写。`pictures` 是实际上传数组，`<Picture N>` 按该数组从 1 编号；`subjects` 映射内容单位与真实 Picture。没有上传的 Audio/Video 标签不能假装有效。镜头切点须递增且小于 frames/fps。

视频参数在设置中人工登记为 `[{"size":"宽x高","frames":整数,"fps":整数}]`，页面显式选择并显示 `frames / fps` 时长，不按秒取整、不改速、不套网上帧数规律。**登记参数不代表真实模型能力已验证**；Iron 仍须匹配已验证流程，否则应 422。每次只提交一个任务、一个最终视频；媒体历史可以播放、恢复和人工采用。保存新片段版本会原子撤销旧视频的当前采用标记，旧文件与确认记录保留为历史。

### 无模型回归

仅在专用副本/目录运行，不启动 `npm start` 或打开业务数据库：

```sh
IRONWEAVE_DRAMA_DATA_DIR=/tmp/专用测试目录/data node --test
# 隔离安装工具后，可启用真实合成媒体解码测试；不调用模型/GPU。
IRONWEAVE_DRAMA_DATA_DIR=/tmp/专用测试目录/data \
IRONWEAVE_FFMPEG=/绝对路径/ffmpeg IRONWEAVE_FFPROBE=/绝对路径/ffprobe node --test
```

新测试覆盖任意 MIME 切分、截断/重复字段/哈希/边界/期限、64 MiB 合成视频缓冲上限、正确多图顺序、accepted 持久化、ACK 丢失、整取恢复、数据库失败补偿、NDJSON/停止/离页/恢复提示、旧依据不采用、片段版本/六段映射。协议和存储测试中的解码器注入只验证接缝，不冒充完整解码；真实解码测试未配置工具时明确跳过。实际 Iron/Node、代理及真实 GPU/POWER 能力仍需独立联调。
